# PersonaBench

A benchmark for evaluating whether language models can infer a person's identity, preferences, and life context from indirect behavioral evidence — specifically, their text messages and calendar events.

## The Problem

Given only the app logs (messenger conversations and calendar events) generated by a synthetic persona, can a language model reconstruct the persona's underlying profile? The benchmark measures social reasoning, theory of mind, and multi-step inference from sparse behavioral signal.

## The Pipeline

PersonaBench synthesizes personas through a six-step pipeline. Steps 1-3 build the personas and their social worlds. Steps 4-6 generate app logs, produce test cases, and run the benchmark.

### Step 1: Seed Persona

Pull a base demographic record from NVIDIA's Nemotron-Personas-USA dataset. The seed contains bare demographic data and short descriptive paragraphs across life domains.

### Step 2: Interview and Extracted Profile

Given the seed, an LLM role-plays the persona and answers a 109-question qualitative life-history protocol adapted from Park et al. (2024). The output is a full interview transcript plus a structured extracted profile.

The extracted profile contains:

| Section | Contents | Purpose |
|---------|----------|---------|
| **preferences** | 18 life-domain subcategories, each with summary, details, and Q## evidence | Structured, auditable record of the persona's preferences and behaviors |
| **summaries** | Free-text analyses from four expert perspectives (demographer, behavioral economist, political scientist, psychologist) | Interpretive narrative for verification and human reference |
| **hidden_facts** | Unified registry of atomic facts for downstream use | The canonical input for all subsequent steps |

Step 2 verification (within the same step folder) runs a four-direction consistency check (seed ↔ interview, interview ↔ profile, profile internal consistency, completeness) and generates the deduplicated `hidden_facts` registry from the verified preferences.

### Step 3: Social Circle

Generate the five people the persona communicates with most in personal (non-work) contexts. Each circle member has demographics, relationship history, personality, shared activities, and evidence citations from the interview.

Step 3 verification confirms circle members are consistent with the interview and extracted profile, and produces a corrected social circle registry.

### Step 4: App Log Synthesizer

Generate messenger snippets and calendar events that implicitly embed the persona's hidden facts through behavioral evidence. The benchmark evaluator sees only these app logs — no persona profile, no interview, no circle metadata.

### Step 5: Test Case Synthesis

Generate benchmark test cases that require the evaluator to recover hidden facts from the app logs alone. Test cases span single-source retrieval, cross-log reasoning, dynamic preference tracking, and multi-source synthesis.

Test cases are verified for human-solvability following the SWE-bench Verified methodology (Jimenez et al., 2024): only cases that a human reviewer can answer using the logs alone are included in the benchmark.

### Step 6: Benchmark Runner

Execute the verified test cases against the model under evaluation and score its performance against the canonical hidden_facts registry.

Each step is self-contained: prompt, verification prompt, generator script, and sample input/output data. The generator script runs the step and, if verification fails, regenerates via an iterative refinement loop.

The 109-question interview table used by Step 2 is a process asset and lives inside the Step 2 folder as a fixed reference file (not as data).

## Reproducibility

All prompts are model-agnostic. Any sufficiently capable language model can run the pipeline. Each step's generator script accepts the previous step's output and produces the next step's input.

See each step's `README.md` for step-specific execution instructions.
